# 자연어 요청을 분석 흐름에 연결하기

Goose는 사용자의 목적·대상·기간·기준시각을 추출해 기존 카탈로그의 보고서와 필요한 전문 스킬을 선택한다. machine ID나 실제 없는 호스트 명령을 만들어 호출하지 않는다.

| 요청 | 읽을 스킬 | 후속 연결 |
|---|---|---|
| 기업·종목·시장·공시·자산 분석 또는 보고서 | Goose의 catalog.json과 workflow-contract.md | 가용 MCP 조회 → 검증 → build_report_input → render_report_html |
| 조건식·종목 탐색·HTS/MTS 등록 | workflows/conditions.md | 지원 조건 검증 → 등록 안내 → 요청한 경우 분석 |
| 논문을 근거로 매수·매도·위험 규칙 설계 | workflows/strategy.md | 규칙 확정 → 사용자가 원하면 과거 검증 |
| 과거 성과·비용·낙폭 검증 | workflows/backtest.md | 데이터/규칙 검증 → 결정적 계산 → 근거 보고 |
| 손실·불안·복구 충동에 대한 지원 | workflows/mental-support.md | 공감·휴식/일지 선택, 요청한 경우에만 투자 분석과 연결 |
| 최초 설정·프로필 수정·키 재사용 | Goose setup 절차 | 지원 로컬 보안 입력·확인 저장 → 동일 런타임 로더 |

복합 요청은 의존 순서를 먼저 정한다. 예를 들어 ‘논문으로 전략을 만들고 검증한 뒤 보고서’는 논문 조사 → 규칙 확인 → 과거 검증 → HTML이다. 규칙이 정해지기 전에 백테스트를 시작하지 않는다. 이미 조회한 동일 공급자·종목·기간의 자료는 같은 요청 내에서 재사용하고 각 조사자가 중복 조회하지 않는다.

독립적인 사업/공시/시장 자료 조사는 호스트가 실제 서브에이전트 도구를 제공할 때만 나눠 실행한다. 한 명이 공급자 요청을 소유하고, 다른 조사에는 비밀·계좌 식별자를 전달하지 않는다. 최종 파일 writer는 한 명이다. 위임 도구가 없는 호스트에서는 같은 단계들을 순차 실행하며 병렬 실행했다고 표현하지 않는다.

결과를 합칠 때 source, provider_as_of, received_at, 단위·통화·결측을 보존하고 상충하는 주장은 출처별로 표시한다. 공통 시점이나 단위가 확인되기 전에는 합산하지 않는다. 실제 지원 도구가 없거나 인증·권리·입력이 부족하면 정확한 오류와 미확보 필드를 반환한다. 계좌 조회·분석은 실제 도구와 정규화가 구현된 범위만 실행하고, 주문·이체로 연결하지 않는다.

HTML은 build_report_input으로 검증한 값을 render_report_html에 전달하고 반환된 리소스를 읽어 확인한다. 실제 값과 합성 값을 섞어 실데이터 완료라고 표시하지 않는다. resource 표시·다운로드의 호스트 지원 여부도 실제 실행과 구분한다.


## 메인 루프와 필요한 절차만 읽기

Goose가 현재 요청의 계획·원자료 참조·검증 결과를 같은 문맥에서 유지한다. 의도 분류, 계획 작성, 기업 분석, 수급 분석, 가치 평가를 각각 별도 대화로 넘기지 않는다. 역할 문서는 필요한 시점에 읽는 전문 절차이며 역할 이름만으로 서브에이전트를 생성하지 않는다.

1. 요청의 대상·기간·보고서 유형과 제외 범위를 확인하고 필요한 카탈로그 항목만 읽는다.
2. 필요한 역할의 PROCEDURE.md를 읽고 기존 도구로 자료를 수집한다. 같은 요청의 공급자·대상·기간·페이지가 같으면 받은 원응답과 영수증을 재사용한다. 다른 기업·시점·페이지의 결과는 합치지 않는다.
3. 같은 루프에서 단위·기간·정정·출처를 검증하고 결정적 계산 도구를 호출한다. 분석 산문은 검증된 근거만 사용한다.
4. build_report_input → render_report_html → resources/read로 진행한다. 프로세스 내 영수증과 리소스 수명을 확인하고 만료 시 다른 자료로 영수증을 대체하지 않는다.
5. 결측·실패는 영향을 받는 섹션에 연결하고 사용자 질문에 대한 결론과 남은 조건을 제시한다. 부분 보고서를 완성으로 세지 않는다.

독립 병렬 수집이나 블랙박스 검수는 실제 위임 도구와 허용된 범위가 있을 때 유지할 수 있다. 입력은 질문·범위·필요한 원자료 참조로 제한하고 결과는 근거 참조·기준시각·단위·결론·반대근거·실패를 함께 받는다. 조사 결과의 요약만으로 원자료를 교체하지 않는다. 출처 검증과 권한·크기·요청 간격 제한은 도구에 유지한다. 전문 절차를 읽었다는 사실은 독립 감사 실행 증거가 아니다.

공개판에서 계좌 요청은 활성 보고서로 연결하지 않는다. ETF는 R12, 국내외 선물은 R13과 가용 읽기 도구로 연결하되 상품 식별·단위·계약·수신 범위를 검증한다. 기존 내부 자료는 보존한다. SEC 연락처, 계약 확인 등 외부 필수 조건은 임의 생성하지 않는다.


공개 발견 스킬은 goose1개이며 조건·전략·백테스트·마음돌보기는 위 workflows/ 참조의 내부 모드다. 명시 모드가 자연어 자동선택보다 우선한다. plan 함수/CLI는 실행권한을 부여하지 않고 관측·오류·근거 영수증을 새로 만들지 않는다.
