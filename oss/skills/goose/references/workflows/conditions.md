
# 조건 설계와 등록 범위

현재 상태는 지침과 설계입니다. 조건식 생성 API·모바일 자동 등록 엔진은 구현되어 있지 않습니다.

1. 시장·증권사·HTS/MTS 제품/버전·종목군·봉 주기·기준시각·사용자 문턱값을 확인합니다. 임의 수익 목표나 손절률을 채우지 않습니다.
2. 조건 설계 역할이 자연어를 `(필드, 비교 연산, 문턱값, 단위, 기간, 세션)`으로 분해하고 데이터 검수 역할이 공식 지원 근거를 확인합니다. 독립 조사가 허용된 host에서만 병렬 조사하며 등록·금융 실행은 위임하지 않습니다.
3. 공식 KIS psearch-title/result 예제는 HTS에서 등록·서버저장한 조건의 조회를 설명하고 결과를 조건당 100건으로 제한합니다. 이는 임의 조건을 생성·저장하는 API가 아닙니다. 현재 패키지에는 이 조회의 MCP binding도 없습니다.
4. MTS의 HTS 연동 검색 지원과 MTS에서 신규 조건을 작성·저장하는 기능을 구분합니다. 현재 앱 화면/버전 근거가 없으면 정확한 메뉴 순서·지원 필드·등록 가능 여부는 미확인으로 표시합니다.
5. 지원 필드만 조건 초안에 연결합니다. unsupported/unknown/partial 상태를 유지하고, 탐색은 U01, 후보 점검은 R10으로 보냅니다. 실제 전 종목 검색 없이 전수 검사했다고 하지 않습니다.

출력은 조건별 설명·공식 출처/확인일·필드/단위/기간·AND/OR 괄호·지원표·사용자가 직접 수행할 확인 단계·미지원 항목입니다. 공유 계약은 `../workflow-contract.md`입니다.

수용: API가 없는 조건 저장 요청→초안과 미지원 표시, 모바일 신규 작성 근거 없음→확정 메뉴 안내 0, 일봉/분봉·원/주 혼용→검수 차단, 100건 응답→전체 시장 완료 주장 0, 키/주문 요청→실행 0. 실제 broker 앱 통합 테스트는 미실행입니다.
