## 2. durable job 상태 계약

### 2.1 상태 (정의서 36행의 7개 상태)

| 상태 | 뜻 | 끝 상태 |
|---|---|---|
| `queued` | 접수, 시작 전 | |
| `running` | 단계 실행 중 | |
| `blocked` | 권한·키·자료·사용자 입력 부족으로 대기 | |
| `partial` | 일부 단계 완료, 나머지 불가 | ● |
| `failed` | 실패 | ● |
| `cancelled` | 취소 확인 | ● |
| `completed` | 전체 완료 | ● |

`running` 중의 **노드 완료와 전체 분석 완료를 구분**합니다(정의서 392행). 노드 상태는 별도 표에 둡니다.

### 2.2 전이

| 현재 | 사건 | 다음 | 조건·기록 |
|---|---|---|---|
| — | 접수 | `queued` | 작업 키(§3)로 중복 확인 |
| `queued` | 시작 | `running` | 권한 재검사(#7 의존) |
| `running` | 노드 완료 | `running` | 노드 결과·입력 해시 저장 |
| `running` | 키 없음·권한 철회·입력 필요 | `blocked` | 사유 코드 |
| `blocked` | 사유 해소 | `running` | 권한 재검사 |
| `running` | 모든 노드 완료 + 검수 통과 | `completed` | |
| `running` | 일부 노드 불가, 나머지 완료 | `partial` | `missing_data` 목록 |
| `running` | 복구 불가 오류 | `failed` | 오류 코드 |
| `running`/`blocked`/`queued` | 취소 요청 | `cancelling`(내부) → `cancelled` | 종속 작업 중단 확인 후에만 `cancelled` |
| `running` | 예산 소진 | `partial` 또는 `failed` | 사유 `budget_exhausted` |
| 어느 상태든 | 권한 철회(로그아웃·구독 만료·수강 기간 종료) | `blocked` → 사용자 선택 | 철회 후 job·cache·파일 차단(정의서 156행), #6 |

### 2.3 저장 위치

- 작업 상태와 노드 결과는 **사용자 PC**에 둡니다(local-first, 정의서 42행; 계좌 자료는 #9 결정에 따라 PC에만).
- 서버로 보내는 것은 entitlement 확인에 필요한 최소 정보뿐(#6, #9). 작업 내용·근거·계산은 보내지 않습니다.
- 보존 기간: **결정 필요**(#9 P-01).

## 3. 중복 실행 0 — 작업 키

- 작업 키 = hash(사용자 principal, 요청 정규형, 대상 식별자, `cutoff_at`, 입력 데이터 스냅샷 해시, 코드 판본).
- 같은 키가 `queued`/`running`/`blocked`이면 새 작업을 만들지 않고 기존 작업 ID를 돌려줍니다.
- 같은 키가 끝 상태면 결과를 재사용할지, 새 분석으로 돌릴지 사용자가 정합니다(정의서 392행 "같은 작업키의 재시도와 새 분석을 구분").
- **키 획득은 배타적 생성으로 합니다.** 덮어쓰지 않는 생성(예: `open(..., O_CREAT|O_EXCL)`, Node `fs.open(path, 'wx')`, 또는 저장소의 유일 제약)으로 키 파일을 만들고, 이미 있으면 실패로 받아 기존 작업 ID를 돌려줍니다. 동시에 두 프로세스가 같은 키를 접수하면 이 생성에 성공한 한쪽만 작업을 시작합니다.
- 임시 파일 → rename은 **이미 획득한 작업 기록을 저장할 때만** 씁니다. 일반 rename은 같은 대상에 대해 두 번 모두 성공하고 앞의 파일을 덮어쓸 수 있으므로(플랫폼에 따라 다름) 중복 방지 수단으로 쓰지 않습니다.

## 4. 취소

- 취소 요청은 즉시 `cancelling`으로 표시하고 새 노드 시작을 막습니다.
- 진행 중인 공급자 호출은 `AbortSignal`로 끊습니다. 현재 코드처럼 취소는 협조적이라 작업자가 신호를 무시하고 계속 돌 수 있습니다.
- 그래서 `cancelled`로 바꾸는 근거는 **작업자가 실제로 끝났다는 관찰**뿐입니다: 작업자의 종료 응답(처리 중이던 promise가 끝남), 또는 강제 종료한 작업자 프로세스·스레드의 종료 확인. **시간 제한에 닿은 것만으로는 확인이 아닙니다**(현재 `withTimeout`도 `role_timeout`을 기록한 뒤 작업자가 계속 돌 수 있음).
- 확인 전까지는 `cancelling`에 머물고, 시간 제한을 넘기면 `cancel_unconfirmed`를 기록해 사용자에게 "멈춤 미확인, 공급자 호출이 이어질 수 있음"으로 보여 줍니다. 강제 종료가 가능한 실행 방식(별도 프로세스 등)이면 그때 종료하고 종료 확인 뒤 `cancelled`로 바꿉니다.
- 취소 뒤 늦게 도착한 결과는 버리고 기록만 남깁니다.

## 5. 재시도

| 오류 | 재시도 | 근거 |
|---|---|---|
| 네트워크 일시 오류, 시간 제한 | 제한 횟수 안에서 지수 대기(횟수 **결정 필요**) | 무한 재시도 금지(정의서 395행) |
| 429 요청 한도 | 공급자가 준 대기 시간 뒤 1회 | 공급자 한도 존중 |
| 401/403 인증·권한 | 재시도 안 함 → `blocked` | 키·권한 문제 |
| 스키마 불일치 | 재시도 안 함 → `failed` | 같은 입력이면 같은 결과 |
| 쓰기 효과가 있는 단계(게시 등) | 결과를 먼저 조회하고, 효과가 없을 때만 재시도 | #23 멱등 키 |

| 예산 | 기본값 | 소진 시 |
|---|---|---|
| 작업당 시간 | 결정 필요 | `partial` 또는 `failed`, 사유 `budget_exhausted` |

## 7. 재현 기록

정의서 38·394행의 재현 패키지 목표:

- 요청 정규형, 작업 키, 코드 판본(빌드 SHA), 입력 데이터 스냅샷 해시, 공급자 응답 영수증 ID와 수신 시각, 노드별 결과 해시, 최종 보고서 해시.
- 비밀·계좌 원문은 넣지 않습니다(정의서 395행). 개인 수치가 필요한 재현은 사용자 PC 안에서만.

## 8. Apps Stock 연계

### 8.1 역할 분리 (정의서 F22)

| 주체 | 하는 일 | 하지 않는 일 |
|---|---|---|
| ATP(플러그인·MCP) | 보고서 생성, 공유판 생성·검수, 게시 요청(#23 API) | DB 직접 SQL, 관리자 도구 노출(정의서 423행) |
| Stock 웹/BFF | 종목 허브·내 보고서·게시판 표시, 저장 | ATP 설치·ATS 가입을 공개 읽기 조건으로 만들기(424행) |
| Stock 저장소 | 게시물·판본·정정·철회 상태의 **유일한 writer** | ID 비밀 복제(424행) |

### 8.2 단일 writer

- 게시물과 그 판본·상태는 Stock 저장소 API 한 곳만 씁니다. ATP는 API를 호출할 뿐 직접 쓰지 않습니다.
- 종목 ID는 F05 식별 결과를 쓰고, Stock 쪽 ID와의 대응표를 한 곳에서 관리합니다(정의서 427행 "동일 종목/콘텐츠 ID 정합").
- 사용자 게시물과 편집부 검수본을 다른 종류로 저장합니다(424행).

### 8.3 정정·철회 전파

#23 §6 표를 그대로 따릅니다: 본문·첨부·검색 색인·캐시·종목 허브·내 보고서 목록. 완료 확인은 공개 URL·검색·첨부를 실제로 열어 차단을 확인하는 것으로 합니다.

## 9. 시험 설계

| # | 시험 | 기대 |
|---|---|---|
| T1 | 같은 작업 키로 두 번 접수(순차) | 작업 1개, 두 번째는 기존 ID |
| T2 | 같은 키로 동시에 두 프로세스 접수 | 배타적 생성 성공 1회, 작업 1개, 다른 쪽은 기존 ID, 작업 기록 덮어쓰기 0 |
| T3 | 실행 중 취소 | 새 노드 시작 0, 작업자 종료 관찰 뒤 `cancelled` |
| T3b | `AbortSignal`을 무시하는 작업자를 취소, 시간 제한 도달 | `cancelled` 아님 — `cancelling` + `cancel_unconfirmed`; 작업자 종료 관찰 뒤에만 `cancelled` |
| T4 | 취소 뒤 늦게 온 결과 | 버림, 기록만 |
| T5 | 시간 제한 → 재시도 | 제한 횟수에서 멈춤, 무한 루프 없음 |
| T6 | 401 응답 | 재시도 0, `blocked` |
| T7 | 실행 중 권한 철회 | `blocked`, 이후 cache·파일 접근 차단 |
| T8 | 프로세스 강제 종료 뒤 재시작 | 마지막 노드부터 재개, 완료 노드 재실행 0 |
| T9 | 예산 소진 | `partial`/`failed` + `budget_exhausted` |
| T10 | 재현 패키지로 같은 입력 재계산 | 노드 결과 해시 일치 |
| T11 | Stock 게시 응답 유실 후 재시도 | 게시물 1개(#23 멱등 키) |
| T12 | 비공개 보고서의 검색 노출 | 0 (정의서 427행) |
| T13 | 다른 사용자의 작업 ID로 `job_get` | 차단 |
