## 문서 상태와 근거

이 문서는 [이슈 #20 요청안 댓글](https://github.com/modu-ai/moai-stock-plugins/issues/20#issuecomment-6758373840)의 검토용 초안을 옮긴 것입니다. **승인 전 공급자 실호출은 금지합니다.** 문서 PR의 병합도 실행 승인이 아닙니다. 승인 여부와 모든 결정란은 미정으로 유지합니다.

아래 코드 동작·줄 번호·수치는 원문 작성 당시의 관찰 기록입니다. 원문은 main `8648ff0d46eead4ce4d757bee05b1de0474670d8`을 기준으로 삼고, 도구 계약·경로 계획은 `09506ef` 빌드에서 확인했다고 밝힙니다. 이 문서화 작업에서는 현재 main의 구현·공식 API 계약·권리·요금을 다시 검증하지 않았습니다. 따라서 아래의 “현재 main”은 그 당시 기준을 뜻합니다. 실행 전 선택값·현재 코드·공식 계약·권한 심사를 별도로 확인해야 합니다.

## 1. 무엇을 승인해 달라는 것인가요

삼성전자(005930)·SK하이닉스(000660)의 **R03 시장 수급**과 **R10 마감 전 거래조건 점검**에 넣을 KIS 원천 자료를 공식 API로 **최대 9번**(핵심안) 읽는 것입니다. 대상 회사·묶음 크기는 7절에서 고릅니다.

## 5. 승인되면 생기는 것 / 안 생기는 것 — **중요**

현재 main 코드에서 이 응답들은 대부분 **원문 표로만** 보고서에 들어갑니다. 지표·차트는 거의 채워지지 않습니다.

| 원천 | 보고서에 들어가는 형태 | 근거 |
|---|---|---|
| 일봉 KIS-039 | `raw_rows` 원문 표(최대 100행). `bars`는 모두 `mapping_status:"blocked"`, OHLCV는 null → `history.close/volume/turnover`는 `missing`, 종가·이동평균 차트와 `metric.ma20`은 생기지 않음 | `history-contract.ts:54-55`, `report-pipeline.ts:303-327` |
| 투자자별 수급 | 원문 표('개인·외국인·기관 순매수 수급'). `flow.*` 지표를 만드는 코드가 없어 R03.S02 막대(`ROUTE_BAR_FIELDS` 349행)는 그려지지 않음 | `report-pipeline.ts:587`, `flow.foreign.net_value` 생산 코드는 `report-observations` 경로뿐 |
| 호가 | 원문 표. `liquidity.best_bid/ask`를 만드는 코드가 없어 `metric.spread_bps`(497~505행)와 R10.S03 산점도는 비어 있음 | `report-pipeline.ts:573` |
| 신용·공매도·대차 | 원문 표. 공식 주수 필드만 단위 확인 후보 | `report-pipeline.ts:565`, `market-risk-data.ts` |
| 당일 분봉 | 원문 결과. 보고서 쪽 전용 표 변환은 확인하지 못함(미확인) | — |

- 생기는 것: 회사별 R03·R10 **실제 원문 부분본**(표 위주). 도구 결과에는 수신 시각·`rights_status: pending`·완전성 미확인 표시(`completeness: unknown` 등)가 들어 있습니다(HTML에 어떻게 보이는지는 미확인).
- 안 생기는 것: 수급 막대, 이동평균선, 스프레드, 누적·강도 계산(R03.S03), 업종·ETF·선물 절(R03.S04·S05), 사용자 조건 판정(R10.S02·S05). 그래서 "완성 보고서"가 아니라 "원문 확인용 부분본"입니다.
- 지표·차트까지 채우려면 승인과 **별도로** 코드 작업이 필요합니다(아래 6절 2).

## 6. 승인 전에 알아 두셔야 할 점

1. **요청 상한과 속도**: 계약 문서(`contracts/kis-api-mapping-v1.json` `rate_limits`)는 실계좌 REST 18건/초, 토큰 발급 1건/초를 적고, 프로토타입 기본값은 "프로세스당 1요청/초, 재시도 없음"입니다. 이 실행도 1요청/초 이하로 순차 실행합니다. 개인 계정의 실제 한도는 확인하지 않았습니다.
2. **승인만으로는 수급·호가·이력 숫자가 지표가 되지 않습니다.** 단위·수정주가 의미가 확정되지 않아서 코드가 일부러 막아 둔 상태입니다. 선택지:
   - (가) 원문 표 부분본만 만들기(이 요청안 그대로)
   - (나) 먼저 단위 검증(공식 문서 대조 + 합성 시험)으로 매핑을 열고 나서 요청 실행 — 코드 PR이 선행
   - (다) 응답을 보고 단위를 검증하는 데 쓰기. 다만 응답 원문을 저장소에 넣을 수 없어 검증 기록 방식을 따로 정해야 함
3. **수급 기간은 정할 수 없습니다.** `inquire-investor`는 날짜를 받지 않고 공급자가 정한 최근 영업일을 돌려줍니다. 원하는 기간이 정확히 나온다고 약속할 수 없습니다.
4. **호가·당일 분봉은 조회 시각에 따라 뜻이 달라집니다.** 장중에는 실시간 호가와 진행 중인 봉이, 장 마감 뒤에는 마감 상태가 옵니다. R10의 "마감 전 점검"이라는 목적에 맞추려면 장중 실행이 필요합니다(정확한 컷오프 시각은 사용자가 정함).
5. **수정주가 코드(`FID_ORG_ADJ_PRC`)**: 공식 예제 기준 `0`=수정, `1`=원주가인데, 코드도 `independently_verified:false`로 표시합니다(`history-contract.ts:53`).
6. 승인과 실행은 별개이며, 실행 시 권한 심사를 따로 거칩니다. 요금은 #17과 같은 조건이고 "비용 0"을 보장하지 않습니다.

## 미확인

- 각 tr_id·파라미터를 공식 포털과 다시 대조하지 않았습니다(코드 계약과 `kis-api-mapping-v1.json`, catalog `2077773a` 기준).

- 개인 계정의 실제 호출 한도·요금.
