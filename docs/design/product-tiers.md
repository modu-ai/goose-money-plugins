## 2. 권한을 이루는 축 (서로 다른 사실로 따로 판정)

| 축 | 뜻 | 판정 주체 | 정의서 대응 |
|---|---|---|---|
| Identity | 검증된 모두의 AI 사용자 | 서버측 토큰 검증 (#6, `docs/design/identity-auth-contract.md`) | F03 |
| Membership | ATP(Stock) 서비스 가입 상태: 가입/정지/탈퇴 | 서비스 DB | F04 UserServiceMembership |
| Subscription | 유료 계약 상태 | 결제 사건 상태기계 | 정의 없음 |
| Learner grant | 수강생 자격에서 오는 부여 — 수강 기간 동안 유료와 동일(결정) | 서비스 DB | 정의서에 없음, 사용자 결정으로 추가 |
| Entitlement | 지금 실행 가능한 기능·한도 = 위 세 축의 함수 | MCP 서버 | F04 ServiceEntitlement |
| Provider readiness | KIS/DART 키 준비 상태 | 로컬 실행기 | F02 |
| Data rights | 공급자 자료의 이용·재배포 권리 | 계약 | 5장 |
| Publication policy | 개별 산출물의 공개 범위 | 게시 검수 | F19 |

규칙(제안):
1. Entitlement는 서버가 Identity → Membership → (Subscription, Learner grant)에서 계산합니다. 모델 입력·클라이언트 플래그·도구 인자는 판정에 쓰지 않습니다(정의서 153행 "모델 입력 user_id를 신뢰하지 않음").
2. Entitlement를 통과해도 Provider readiness와 Data rights는 따로 검사합니다. 유료는 자료 재배포 권리나 주문 권한을 만들지 않습니다.
3. 필요한 축만 검사합니다. 공개 공시만 쓰는 기능은 KIS 준비를 요구하지 않습니다(HEAD는 이미 공급자별 스위치 — `credential-runtime.ts` `localReadSwitches`).

수강생 판정 규칙(결정 반영):
- 수강생 권한은 Subscription과 **별도 축**(Learner grant)으로 저장하고, 기간(시작·끝)을 가진다. 기간 값은 수강 기록에서 오며 이 문서는 정하지 않는다.
- Entitlement = max(무료, 구독 유효 시 유료, 수강 기간 중 유료). 수강 기간이 끝나도 구독이 유효하면 유료 유지, 둘 다 없으면 무료로 복귀.
- 무료로 복귀해도 사용자 PC에 저장된 계좌 자료는 지우지 않는다(사용자가 지울 때까지 — #9 결정). 유료 기능으로 다시 여는 것만 막는다.

## 5. 공개 정책 우선순위 (제안)

정의서 확정값: 무료판 공개 필수, 수강생 공개 선택, 개인 보유 원본 기본 비공개, 계좌·잔액·수량·원가·개인 손익·토큰은 게시물에서 기본 제외(380행).

| 순위 | 규칙 | 이유 |
|---|---|---|
| 1 | 개인 금융정보·비밀은 어떤 등급에서도 공개하지 않음 | 정의서 42·380행. "공개 필수"는 개인정보 공개 의무가 아님 |
| 2 | 권리 불명확·검수 fail/unknown → 보류 | 377행 |
| 3 | 수강생 선택(비공개 선택 시 미공개) | 381행 수용시험 |
| 4 | 무료판 공개 필수 = **공유판(redacted)**에만 적용 | 606행 원본/공유판 분리 |
| 5 | 유료판 기본값 | **결정 필요** |

결정 필요:
- 무료 사용자가 공개를 거부하면 어떤 기능까지 쓸 수 있는지(생성은 허용하고 게시만 막을지, 생성 자체를 막을지).
- 수강생이면서 유료인 사용자의 공개 기본값.
- 개인 계좌 분석(유료)에서 나온 보고서의 공유판 허용 여부.

## 6. 기능 게이트 응답 계약 (제안)

| 상황 | 응답 코드 | 사용자 표시 |
|---|---|---|
| 미로그인 | `auth_required` (정의서 40행 예외 목록) | 로그인 안내 |
| 로그인했지만 미가입 | `membership_required` | 가입 경로 |
| 정지·탈퇴 | `membership_inactive` | 사유·복구 경로(정의서 169행) |
| 유료 기능, 구독 없음 | `entitlement_required` | 해당 기능만 잠김, 무료 기능 계속 |
| 한도 초과 | `entitlement_limit_reached` | 남은 기간 |
| 공급자 키 없음 | `provider_unavailable` | 해당 공급자 기능만 |
| 범위 밖(R13/R14/주문) | `unsupported` | 제외 사유 |

판정은 모든 도구 호출과 `resources/read`에서 서버가 합니다. 자원 URI를 추측해도 열리지 않아야 합니다.

## 7. 수용 시험 목록 (부정 시험 중심)

1. 무료 사용자가 유료 도구를 직접 호출 → `entitlement_required`, 공급자 호출 0.
2. 클라이언트가 `tier:"paid"` 같은 필드를 넣어도 판정 불변.
3. 구독 만료 시점 이후 첫 호출부터 유료 기능 차단, 이미 만든 비공개 보고서는 본인 열람 유지(결정 필요: 열람 유지 여부).
4. 공개 공시만 필요한 기본 보고서는 KIS 키 없이 동작.
5. R13·R14·주문 요청은 유료여도 `unsupported`.
6. 수강생 비공개 선택 시 게시 0.
7. 무료 공개 필수 경로에서 개인 보유 수치가 공유판에 0건.
8. 다른 사용자의 보고서 자원 URI → 차단.
