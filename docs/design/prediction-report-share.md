## 1. 범위와 판 구분

#149의 흐름: 장 시작 전 사용자가 시가·종가 예측과 이유를 입력 → Goose가 종목 분석과 사용자 논리를 구분한 초안 생성 → 사용자가 확인한 공유판을 커뮤니티 예측 게시물에 연결. 이 저장소(플러그인)는 입력 수집·초안 조립·공유판 생성·게시 요청까지이고, 예측 게시물의 저장·마감 판정·채점은 커뮤니티 쪽(§10 역할 분리, 상위 #728)입니다.

| 판 | 내용 | 저장 위치 | 공개 |
|---|---|---|---|
| 예측 원본 | 사용자가 제출한 예측값·이유·시각(§2 입력의 확정본) | 사용자 PC(#9와 동일 원칙) | 하지 않음 |
| 예측 근거 보고서 원본 | AI 초안 포함 전체 보고서(§3). `report-input.json`·계산 원장 포함 | 사용자 PC | 하지 않음 |
| 공유판 | pub §2의 분리·해시 규칙을 그대로 적용한 새 판본(원본 불변, 원장 미첨부) | 게시 전 사용자 PC, 통과 후 서비스 | pub §1 등급 규칙 |
| 예측 게시물 | 공유판을 커뮤니티에 등록한 결과(post_id, §5) | Stock 저장소(유일 writer, dur §8.2) | 커뮤니티 정책 |

보고서 생성 / 예측 제출 / 게시물 공유는 **별도 동작**입니다(§4). "생성만 요청했을 때 자동 게시하지 않는다"가 이 계약의 원칙이며 pub §1의 자동 등록 루틴과의 관계는 D-01 결정 대기입니다.

## 3. AI 초안의 구성 (신규)

초안은 아래 네 칸으로 나눠 조립하고, 칸 경계가 문서에서 시각적으로 구분됩니다.

| 칸 | 내용 | 규칙 |
|---|---|---|
| 검증된 사실·출처 | 공급자 응답 기반 수치·공시·뉴스. 출처·기준 시각·단위 필수 | pub §3 C4 자료 적합성 기준을 생성 단계부터 적용 |
| 사용자 가설 | §2의 사용자 이유 원문 | AI가 재서술·요약·변형하지 않음(원문 보존) |
| AI 해석 | 사실 칸과 가설 칸을 잇는 해석. 어떤 수치도 새로 만들지 않음 | 검수는 C3(수익 보장·투자 권유 문구 금지)·C4 적용 |
| 반대 근거·불확실성 | 반대 방향 근거와 자료 한계 | 분석 실패·자료 부족은 칸을 비우지 않고 UNKNOWN/부분 결과로 표시(pub §3 unknown 정의·dur §2 `partial` 재사용) |

금지: 존재하지 않는 출처 생성, 개인 의견 삽입, 수익 보장 표현(pub C3), 매매 실행·주문 유도(범위 밖). 초안은 기존 R01 계열 보고서 판본 계약(report_id/version/hash) 위에 조립하되, 예측 절의 네 칸 구조가 이 계약의 추가 사항입니다.

## 4. 생성·제출·공유의 별도 동작

| 동작 | 시작 | 결과 | 자동 진행 여부 |
|---|---|---|---|
| 보고서(초안) 생성 | 사용자 요청 | 예측 근거 보고서 원본 판본 | 다음 동작으로 **자동 진행 없음** |
| 예측 제출 | 사용자 확인 입력 | 예측 원본 확정 + prediction_id | 자동 없음(확인 필수) |
| 게시물 공유 | 사용자 확인 입력 | pub §4 상태 전이(draft→reviewing→publishing→published) | 검수 통과분 자동 등록 여부는 **D-01** |

불확실 전송(공유 요청 응답 유실)은 pub §5·#45 하네스 계약 그대로: 같은 멱등 키로 조회 1회 뒤에만 재시도, 쓰기 자동 재전송 없음.

## 5. 식별자 결합 (신규)

| 식별자 | 정의 | 근거 |
|---|---|---|
| `prediction_id` | hash(사용자 principal, 종목 식별자, 거래일) — 1인·종목·거래일에 1건(중복 제출은 pub §5 멱등 키로 판별) | 제안(제출 정책·동점 처리는 #728) |
| `report_id`/`version`/`hash` | 기존 보고서 판본 계약 그대로 | 재사용(공유판 해시는 pub §2·§5) |
| `post_id` | 게시 등록 receipt의 게시 ID(pub §5 receipt) | 재사용 |
| source timestamp | 수집 시각·cutoff — dur §7 재현 패키지 재료 | 재사용 |
| 모델/템플릿 버전 | 초안 생성에 쓴 템플릿·렌더러 판본. dur §7의 코드 판본(빌드 SHA) 슬롯에 담음 | 제안 |

결합 규칙(제안): 공유 요청은 `prediction_id + report_id/version/hash + post_id`를 한 receipt로 남기고, 커뮤니티 서버가 마감 여부·예측값 유효성을 **서버 쪽에서 재검증**합니다(#728 수용 기준 — 클라이언트 선언을 신뢰하지 않음). 마감 검증 오류 코드는 D-04 확정 뒤 지정.

## 6. 마감 잠금과 정정

- 잠금(커뮤니티 서버가 거래일 마감 선언) 뒤에는 예측값·사용자 이유·잠긴 시점의 근거 판본을 **덮어쓰지 않습니다**. 잠금 시각·소급 변경 금지 범위·점수 불변 규칙은 #728 소관입니다.
- 잠금 이후 보고서 정정은 pub §4 원칙을 그대로: 변경 시 새 판본으로 재검수하고 이전 판본에 "정정됨" 표시, 전파는 pub §6 표(본문·첨부·색인·캐시·종목 허브)를 따릅니다.
- 공개 철회·권한 회수(구독 만료 등)는 pub §4 `withdrawn` 전이·dur §2 권한 철회 `blocked`를 재사용. 삭제·탈퇴 시 게시물 처리는 pub G-05, 보존 기간은 G-03·J-03 결정 대기.

## 7. 작업 실행·실패·재시도

세 동작(§4)은 전부 durable job(dur §2 상태 7종·§3 작업 키·§4 취소 관찰 원칙·§5 재시도 분류) 위에서 실행합니다. 작업 키 재료(dur §3의 여섯 가지)에 `prediction_id`를 추가하는 것을 제안합니다.

| 단계 구분(#149 AC7) | 매핑 | 근거 |
|---|---|---|
| 초안 생성 성공 | dur `completed`(또는 `partial` — 부분 결과 표시) | dur §2 |
| 게시 접수 | pub `publishing` 진입(멱등 키 발급) | pub §4·§5 |
| 게시 확정 | pub `published` + receipt(post_id) | pub §4·§5 |
| 실제 조회 | 응답 유실 시 같은 키로 조회 1회 → 결과 조정 | pub §5·#45 계약, dur §5 "쓰기 단계는 조회 후 재시도" |

현재 main에는 순수 로직 조각만 존재하고(dur §1 — 실행기·DB·영속 복구·Stock 연결 미착수), 이 문서는 그 구현을 요구하지 않습니다(승인 후 카드 분할은 §10).

## 10. 소유권·구현 카드 분할

역할 분리는 dur §8을 그대로: ATP(플러그인)는 생성·공유판·게시 요청만, Stock 저장소가 게시물 상태의 유일 writer(dur §8.2), Stock 웹/BFF는 표시·저장 보조(dur §8.1). Stock 쪽 실체는 mo.ai.kr #603(설계 게이트 — 사용자 결정 전 보류)이며 이 저장소에서 구현하지 않습니다. Stock 저장소 API 계약은 dur J-05와 같은 대상입니다(웹 쪽 소유).

이 문서 승인 시 구현 카드 분할 후보(제안 — 분할 확정은 별도): ① 예측 입력 스키마·오류 코드(D-04 확정 후) ② 초안 네 칸 조립 ③ 식별자 결합·receipt ④ 공유 UI 흐름 ⑤ 시험(P1~P7 + 재사용 목록 연결). 각 카드의 인수 조건은 대응하는 수용 기준 항목과 이 문서의 절 번호로 지정합니다.
