- 작성: 2026-11-10 설계 감사.

## 1. 공개 범위 규칙과 출처

| 규칙 | 출처 | 상태 |
|---|---|---|
| 무료판은 공개 필수 | 정의서 376·640행 F19 "무료판 공개 필수"; #5 사용자 결정(2026-11-10) 유지 | 확정 |
| 수강생은 모두의 주식 환경설정에서 공개 여부 선택 | 정의서 376·640행; #5 결정 | 확정 |
| 개인 보유 원본은 기본 비공개 | 정의서 17·42행; #9 결정(계좌 자료는 사용자 PC에만) | 확정 |
| 계좌·잔액·수량·원가·개인 손익·토큰·캡처·숨은 메타데이터는 게시물에서 기본 제외 | 정의서 380행 | 확정 |
| 사람 관리자 승인 없이 에이전트 검수 통과분만 자동 등록·공개 | 정의서 377·640행 "2026년 11월 8일 확정 루틴" | 확정 |
| 불통과·판단불가는 공개 보류 + 사유 기록 | 정의서 377행 | 확정 |
| 내용·첨부·대상·공개범위가 바뀌면 그 판본 재검수 | 정의서 377행 | 확정 |
| 유료판 공개 기본값 | — | **결정 필요** (#5 D-05) |
| 보존 기간·정정/철회·신고 처리 세부 | 정의서 640행 "남은 결정" | **결정 필요** |

규칙끼리 부딪힐 때의 순서(제안): ① 개인 금융정보·비밀 제외 → ② 권리 불명확·검수 fail/unknown 보류 → ③ 수강생 비공개 선택 → ④ 무료판 공개 필수는 **공유판에만** 적용 → ⑤ 유료판 기본값. "공개 필수"는 개인 자료를 공개할 의무가 아니며, 공유판을 만들 수 없으면 보류합니다.

## 2. 원본과 공유판 분리

정의서 606행: 보고서 입력 JSON도 개인정보를 담을 수 있으므로 생성 원본과 공유용 파일을 분리합니다.

| 판 | 내용 | 저장 위치 | 공개 |
|---|---|---|---|
| 원본 | 보고서 HTML, `report-input.json`, 계산 원장, 개인 입력 | 사용자 PC (#9) | 하지 않음 |
| 공유판 | 원본에서 **만든** 새 판본. 개인 수치·숨은 메타데이터·내부 식별자 제거, 첨부는 허용 목록만 | 게시 전에는 사용자 PC, 통과 후 서비스 | 검수 통과 시 |

- 공유판은 원본을 고쳐 만들지 않고 새로 생성합니다(원본 불변).
- `report-input.json`·계산 원장은 공유판에 첨부하지 않습니다(정의서 606행 "source-ledger만 공개한다고 안전하다고 가정하지 않음").
- 공유판 해시 = 본문 + 첨부 + 대상 + 공개범위 + 정책 판본을 정규화해 계산(§5 멱등 키의 재료).

## 3. 검수 항목과 판정 기준

판정값은 `pass` / `fail` / `unknown` 세 가지입니다. **하나라도 `fail`이면 fail, `fail`이 없고 하나라도 `unknown`이면 unknown, 모두 `pass`일 때만 pass**입니다.

| # | 항목 | pass | fail | unknown |
|---|---|---|---|---|
| C1 | 개인 금융정보 | 계좌번호·잔액·보유 수량·평균단가·평가액·개인 손익이 본문·첨부·메타데이터에 0건 | 하나라도 발견 | 이미지·PDF 안 글자처럼 검사기가 읽지 못한 영역이 있음 |
| C2 | 민감정보·비밀 | 키·토큰·인증 헤더·키 포함 URL·이메일·전화번호 0건 | 발견 | 판독 불가 영역 |
| C3 | 공개 규약 | 서비스 게시 규약의 금지 항목(투자 권유·수익 보장 표현 등) 0건 | 위반 문구 발견 | 규약 판본을 불러오지 못함 |
| C4 | 자료 적합성 | 모든 수치에 출처·기준 시각·단위가 있고 합성값·추정값이 실측처럼 표시되지 않음 | 출처 없는 수치, 합성값을 실측으로 표시 | 출처 링크 접근 불가 |
| C5 | 회원·소유권 | 게시 요청자 = 보고서 소유자(서버가 토큰 principal로 판정, #6) | 다른 사용자 보고서 | 소유 기록 조회 실패 |
| C6 | 권리 | 인용한 공급자 자료의 재배포 권리 확인됨 | 재배포 금지 자료 포함 | 권리 상태 미확인(`rights_pending` 등) |
| C7 | 해시 | 검수한 공유판 해시 = 등록하려는 해시 | 불일치(검수 뒤 바뀜) | 해시 계산 실패 |
| C8 | 공개 정책 | 등급별 규칙(§1) 충족, 수강생 선택값 확인 | 수강생이 비공개 선택 | 선택값 조회 실패 |

**unknown의 정의**: 검수기가 판정에 필요한 입력을 얻지 못했거나 읽지 못한 경우입니다. unknown은 pass로 올리지 않고 보류합니다. 재시도는 같은 판본에 대해서만 하며, 사람이 대신 통과시키는 경로는 두지 않습니다(정의서 377행).

검수 기록에 남기는 것: 검수한 공유판 해시, 정책 판본, 항목별 판정과 사유 코드, 검수 시각, 검수기 판본. 개인 수치 자체는 기록하지 않습니다(사유 코드와 위치만).

## 4. 상태 전이

| 현재 | 사건 | 다음 | 비고 |
|---|---|---|---|
| `draft` | 게시 요청 | `reviewing` | 공유판 생성·해시 고정 |
| `reviewing` | 전 항목 pass | `publishing` | |
| `reviewing` | fail | `held_fail` | 사유 기록, 공개 0 |
| `reviewing` | unknown | `held_unknown` | 사유 기록, 공개 0 |
| `held_*` | 공유판 수정 | `reviewing` | 새 해시로 재검수 |
| `publishing` | 등록 성공 | `published` | receipt 저장 |
| `publishing` | 응답 유실 | `publishing` | 같은 멱등 키로 조회 후 재시도(§5) |
| `published` | 내용·첨부·대상·범위 변경 | `reviewing` | 새 판본, 이전 판본은 정정 처리 |
| `published` | 철회 요청 | `withdrawn` | 전파(§6) |
| `published` | 권리 만료 감지 | `withdrawn` | 사유 `rights_expired` |
| 어느 상태든 | 소유자 탈퇴 | 결정 필요 | #9 P-03 (철회 / 익명화 / 유지) |

## 5. 멱등 키

- 키 = hash(소유자 principal, 보고서 판본 ID, 공유판 해시, 공개범위, 대상 게시판).
- 같은 키로 두 번 등록하면 서버는 첫 receipt를 돌려주고 새 게시물을 만들지 않습니다.
- 응답 유실 뒤에는 먼저 키로 게시 상태를 조회하고, 없을 때만 다시 등록합니다.
- 공유판 해시가 바뀌면 키도 바뀌므로 재검수가 강제됩니다.
- receipt에는 게시 ID, 접근 URL, 공유판 해시, 등록 시각을 담고, 등록 뒤 URL을 열어 해시를 대조합니다(정의서 603행 "실제 대상/접근/판본 확인").

## 6. 정정·철회 전파

| 대상 | 정정 | 철회 |
|---|---|---|
| 게시물 본문 | 새 판본 게시, 이전 판본에 "정정됨" 표시와 링크 | 비공개 처리 |
| 첨부 | 새 판본 첨부로 교체 | 접근 차단 |
| 검색 색인 | 재색인 | 색인 제거 |
| 캐시·CDN | 무효화 | 무효화 |
| 종목 허브·내 보고서 목록(F22) | 최신 판본 링크로 갱신 | 목록에서 제거 |
| 알림 | 결정 필요 | 결정 필요 |

완료 확인: 철회 뒤 공개 URL·검색 결과·첨부 URL 접근이 모두 차단됐는지 실제로 열어 확인합니다.

## 7. 제안 API (정의서 6장 591행 이름 사용, 미등록)

| 이름 | 입력 → 출력 |
|---|---|
| `report_publish_prepare` | 보고서 판본·대상·공개범위 → 공유판 미리보기, 해시, 검수 결과 |
| `report_publish_commit` | 멱등 키 → receipt 또는 보류 사유 |
| `report_publication_get` | 게시 ID 또는 멱등 키 → 상태·URL·판본 이력 |
| `report_withdraw` | 게시 ID → 철회 receipt |

이 이름들은 아직 `tools/list`에 없습니다. 설치 문서나 화면에 있는 것처럼 표시하지 않습니다(정의서 575행).

## 8. 수용 시험 (정의서 381행 기반)

1. 수강생이 비공개 선택·취소 → 게시 0.
2. 검수 통과 판본만 자동 등록·공개.
3. fail·unknown → 공개 0, 사유 기록.
4. 무료판 공개 필수와 수강생 공개 선택 범위 보존.
5. 판본·범위 변경 → 재검수.
6. 다른 사용자 ID로 게시 요청 → C5 fail.
7. 같은 멱등 키 두 번 commit → 게시물 1개.
8. commit 응답 유실 → 재시도해도 게시물 1개.
9. 민감 첨부(계좌 캡처 등) → C1 fail 또는 unknown.
10. 악성 HTML(스크립트·외부 추적 픽셀) → 공유판 생성 단계에서 제거, 남으면 fail.
11. 권리 만료 → 자동 철회.
12. 철회 → 검색·캐시·첨부 전파 확인.
13. 공유판에 `report-input.json`·계산 원장 첨부 0.
