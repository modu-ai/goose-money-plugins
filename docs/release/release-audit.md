# 릴리즈 전 전체 변경분 검수 절차

Refs #130 · 운영 절차이며 실제 검수·출시 완료 기록이 아닙니다.

PR에서는 기존의 가벼운 확인을 유지하고, 무거운 전체 변경분 검수는 **릴리즈 배포 전에 한 번** 수행합니다. 이 문서는 릴리즈 준비 판단을 위한 수동 절차입니다. 기존 자동 워크플로·필수 검사는 바꾸지 않으며, 새 PR 자동 게이트나 required check를 추가하지 않습니다. 수동 워크플로 실행, 배포 명령, 태그 생성이나 저장소 보호 규칙 변경도 요구하지 않습니다.

## 1. PR에서 계속 확인할 것

- 현재 PR head의 **full SHA**와 기존 `test (macos-latest)`·`test (windows-latest)` 두 시험의 실행 URL·대상 SHA·결과를 확인합니다. 일부 시험만 통과한 것을 두 시험의 완료로 적지 않습니다.
- 작성자와 별도의 검토자가 변경분을 독립 검토하고, 검토한 full head SHA·결과·남은 조치를 PR에 기록합니다.
- Codex 리뷰 요청 댓글과 **도착한 리뷰 결과**를 구분합니다. 요청 댓글만으로 완료나 통과로 보지 않습니다. 코드·보안 리뷰 결과 댓글/산출물이 실제로 어느 full head SHA를 검토했는지 확인하고 현재 PR head와 대조합니다. SHA를 확인할 수 없거나 결과가 없으면 미확인으로 기록합니다.
- head가 바뀌면 이전 시험·검토·Codex 결과를 새 head의 증거로 간주하지 않습니다. 확인 시점의 head와 증거의 일치 여부, 미확인 항목을 PR에 남깁니다. 이는 기존 확인을 유지하는 수동 기록이지 새 자동 PR 차단 게이트가 아닙니다.

## 2. 릴리즈 범위 고정

검수 담당자는 다음을 먼저 기록하고, 이 범위를 모든 시험·리뷰·감사의 공통 기준으로 사용합니다.

1. 릴리즈 후보 커밋의 full SHA를 고정합니다. 브랜치 이름이나 `HEAD`라는 표기만으로 대신하지 않습니다.
2. 실제로 배포된 **직전 릴리즈의 태그**와 그 태그가 가리키는 커밋의 full SHA, 해당 릴리즈 URL을 기록합니다. 최신 태그라는 이유만으로 직전 실제 릴리즈로 간주하지 않습니다.
3. 검토 범위를 `<직전 릴리즈 태그>..<후보 full SHA>`로 적고, 양 끝의 고정 SHA와 전체 변경 파일·커밋 목록을 보존합니다. PR 하나나 일부 파일만으로 범위를 줄이지 않습니다.

태그가 있는 실제 릴리즈가 없거나 직전 릴리즈를 확인할 수 없으면 **범위 결정 필요 / 미검증**으로 기록합니다. 임의의 최초 커밋·분기점·최근 PR을 baseline으로 만들지 않습니다. 릴리즈 책임자가 초기 릴리즈의 검토 범위와 근거를 결정해 기록한 뒤에만 검수를 진행합니다.

## 3. 고정된 후보 검수

1. **전체 시험 2종**: 고정 후보 SHA에 대한 기존 `test (macos-latest)`·`test (windows-latest)`의 전체 실행이 모두 성공했는지 확인합니다. `.github/workflows/test.yml`의 전체 시험 결과(예: 후보 자체에 대한 기존 main push 실행)를 사용하며, 실행 URL·실제로 checkout하여 검증한 커밋의 full SHA·완료 상태·결과를 기록합니다. PR 이벤트의 head 메타데이터와 실제 checkout된 병합 커밋은 다를 수 있으므로 초록 체크나 head 표시만으로 후보 검증을 인정하지 않습니다. PR의 이전 head나 후보와 다른 merge SHA에서 성공한 결과는 대신 쓰지 않습니다. 해당 후보의 결과가 없으면 미검증입니다.
2. **Codex 코드·보안 리뷰**: 고정한 전체 범위를 명시해 코드 리뷰와 보안 리뷰를 받습니다. 각 결과의 원문 URL/산출물, 검토한 양 끝 SHA, 완료 여부, findings와 해결 여부를 기록합니다. 두 리뷰를 구분해 결과를 남기고, 개별 PR 리뷰를 모은 것만으로 릴리즈 전체 변경분 리뷰를 대신하지 않습니다. 요청 접수·실행 중·결과 누락·검토 범위나 SHA 불명은 완료가 아닙니다.
3. **별도 독립 감사 1회**: 구현자 및 위 Codex 리뷰와 별개의 감사자가 같은 전체 범위, 시험·코드·보안 결과, findings 조치를 대조합니다. 감사자·검토 범위·후보 full SHA·판정·미검증·남은 조치를 별도 감사 기록으로 남깁니다. PR 단계의 독립 검토나 Codex 결과를 이 감사로 중복 계산하지 않습니다.
4. **최종 커밋 대조**: 릴리즈 준비 판정 직전에 현재 후보 full SHA를 다시 확인하고 모든 증거의 후보 SHA와 일치하는지 확인합니다. 태그의 해석 결과도 고정한 기준 SHA와 대조합니다.

후보 커밋이나 기준 범위가 바뀌면 이전 증거는 이전 후보의 기록으로만 보존합니다. **새 후보에 재사용하지 않고** 범위를 다시 고정한 뒤 전체 시험 2종·전체 범위 코드/보안 리뷰·독립 감사를 새 기준으로 다시 수행합니다. findings 수정으로 후보가 바뀌는 경우도 같습니다.

## 4. 통과 기준과 결과 기록

기존 `.moai/reports/` 관례에 따라 `.moai/reports/<릴리즈 검수 식별자>/`에 기록합니다. 이슈 기반 작업은 식별자에 이슈 번호를 포함합니다. 후보별 기록을 구분하고, 요약은 `verdict.md`, 원문 결과는 같은 디렉터리의 산출물이나 접근 가능한 원문 URL로 연결합니다. 감사 원문은 요약과 별도로 보존합니다. 비밀값은 넣지 않습니다.

이 경로는 Git에 포함되지 않는 로컬 보존 위치이므로, 릴리즈 책임자가 확인할 수 있는 원문 URL이나 보존 위치도 기록합니다. 공개 게시를 뜻하지 않습니다.

요약에는 다음을 남깁니다.

- 기록일·검수 담당자·릴리즈 책임자, 직전 실제 릴리즈 URL·태그·기준 full SHA, 후보 full SHA, 전체 검토 범위와 변경 목록 위치
- 전체 시험 2종 각각의 실행 URL·full SHA·결과, Codex 코드/보안 리뷰 각각의 원문·범위·full SHA·findings 및 조치 근거
- 별도 독립 감사 원문·감사자·범위·후보 full SHA·판정, 최종 커밋 대조 결과
- 항목별 및 종합 **통과 / 실패 / 미검증**, 미해결 findings·남은 조치·담당자, 릴리즈 준비 판단과 판단자

**통과**는 범위가 확정되고, 같은 후보의 전체 시험 2종이 모두 성공하며, 전체 범위 Codex 코드·보안 리뷰가 완료되어 미해결 findings가 없고, 독립 감사도 통과하고, 최종 커밋 대조가 일치할 때만 기록합니다. 실패한 시험·미해결 findings·감사 실패는 **실패**, 결과 누락·진행 중·범위/SHA 불명·불일치는 **미검증**입니다. 실패나 미검증이 남으면 릴리즈 준비 통과로 판정하지 않고 남은 조치를 기록합니다. 무응답이나 검사 행의 존재만으로 통과시키지 않습니다.

이 검수의 통과는 실제 배포·게시나 공개 승인이 아닙니다. 기능별 출시 준비 상태는 [기능 준비 현황](feature-readiness.md), 저장소 공개·이미지 출처·라이선스 등의 결정은 [공개 전 점검 목록](public-release-checklist.md)을 별도로 확인합니다. 해당 문서의 미결정 사항을 이 절차의 통과로 해소했다고 간주하지 않습니다.
