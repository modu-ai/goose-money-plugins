# 근거 기반 보고서 산문 작성

## 실행 순서

요청 목적과 보고서 유형 선택 → 필요한 MCP 자료 조회 → 종목·시점·기간·단위·통화·페이지 범위 정규화 → 결정론적 지표 계산 → 아래 분석 프롬프트로 산문 작성 → 근거 대조 → 기존 유형별 템플릿 렌더링. 의존 없는 자료 조사만 병렬로 하고 공급자 중복 호출과 같은 파일의 동시 수정을 피합니다.

## 분석 프롬프트

당신은 사용자가 이해할 수 있는 투자 자료 분석을 작성한다. 입력은 보고서 유형, 섹션 목적, 검증된 관측값, 계산 결과와 산식 버전, 출처, 기준일·수집시각, 기간, 단위·통화, 수신 범위, 결측 이유다. 이 입력에 없는 수치나 사건을 만들지 않는다.

각 섹션은 ‘확인된 사실 → 계산 결과 → 의미와 해석 → 반대 신호·다른 설명 → 모르는 것 → 판단이 달라질 조건과 다음 확인’ 순서로 자연스러운 한국어 문단을 작성한다. 질문의 성격에 맞춰 불필요한 단계를 줄일 수 있지만 관측과 해석을 섞지 않는다. 중요한 문장에만 굵은 강조를 쓰며 표·차트를 다시 숫자 목록으로 반복하지 않는다. 독자가 알아야 할 이유와 제한을 함께 설명한다.

- 사실: source_id와 근거 필드·기준일을 연결한다.
- 계산: 입력값·산식·기간이 일치할 때만 계산 결과를 사용한다.
- 해석: 사실에서 가능한 설명임을 밝히며 인과를 단정하지 않는다.
- 가설: 확인해야 할 조건을 함께 쓰고 사실로 표현하지 않는다.
- 수급: 외국인·기관·개인의 수량/금액/기간을 구분한다. 외국인 보유율은 순매수가 아니다.
- 재무: 연결/별도·기간 흐름/기말 잔액·원문 통화·금액 배율을 구분한다. account_id 같은 내부 식별자는 본문 표에 노출하지 않는다. 당기·전기 비교가 불가능하면 비율을 만들지 않는다.
- 뉴스·공시: 제목만 받은 경우 본문을 읽었다고 하지 않는다. 발표·관측·수집시각을 구분하고 정정·철회 가능성을 남긴다.
- 결측: 미호출, 응답 없음, 매핑 미구현, 계산 불가, 정상 자료 부재를 구분하고 0이나 가상 값으로 메우지 않는다.
- 주문·이체·계좌 조회를 수행하지 않는다. 개인 투자자의 수익·가격 방향을 보장하지 않는다.

## 검수와 출력

산문에 쓴 모든 수치가 근거 묶음과 일치하는지, 기간·단위·출처가 유지되는지 검사한다. 계산은 언어모델에 재계산을 맡기지 않는다. 실패한 단락은 근거를 보완하거나 결측으로 남긴다. 기존 디자인의 제목·표·LWC/ECharts 금융 차트·Pele 관계/절차 도식을 유지한다. HTML 생성만으로 호스트 표시 또는 실데이터 전체 완성을 주장하지 않는다.

`build_report_input`이 반환한 원본 ReportInput은 변경하지 않는다. 호스트는 `moai.report.narrative-draft.v1` 초안을 작성하고 `render_report_html`의 선택 입력 `narrative_draft`로 전달한다. 초안에는 보고서 ID, 섹션별 문단, 출처·지표 참조, 결론 우선 Goose 오피니언과 상세 근거·위험·다음 확인을 넣는다. 각 문단은 사실·계산·해석·한계·조건을 구분한다.

산문의 숫자는 직접 쓰지 않고 `{{price}}`처럼 bindings에 연결한다. metric 바인딩은 정확한 source_id와 metric_id, raw/grouped 표시를 지정한다. 미확인 단위·결측·권리 대기 지표는 숫자 산문에 사용할 수 없다. 수급 원문 부호로 계산한 순매수 일수는 무차원 관측 빈도이며 누적 수량·금액·매수 강도가 아니다. 원문 단위와 기간 완전성을 확인하기 전에는 환산·누적을 하지 않는다.

렌더 도구는 원본 보고서의 근거 해시를 검사한 뒤 초안의 참조·숫자 바인딩을 검증한다. 초안은 원천 값·권리·검증 상태를 바꾸지 못한다. `host_draft_applied_unverified`는 호스트가 작성한 해석이 연결됐다는 뜻이며 독립 검증된 결론이나 모든 API·보고서의 완성을 뜻하지 않는다. `resources/read`로 실제 HTML을 받아 근거 수치와 문단·마지막 Goose 오피니언을 검수한다.

## 모든 활성 보고서의 공통 필수 지침

개인 투자자의 의사결정에 필요한 핵심 요약, 수치가 중요한 이유의 쉬운 설명, 유형별 실제 근거와 해석, 위험·반대 신호, 다음 관찰 조건을 제공한다. 수급은 주체별 순매수, 실제 수신일의 지속성, 같은 기간 가격·거래량과 대조한다. 기간·단위를 확인하지 못하면 지속성 점수나 투자자의 의도를 추정하지 않는다.

마지막 섹션은 ‘Goose 오피니언’이다. 종합 결론과 전망을 먼저 말하고 아래에 실적·밸류에이션·추세·수급의 지지 근거와 반대 근거를 상세히 설명한다. 관측 사실·결정론적 계산·AI 의견을 구분하며 현실적인 선택지와 위험·관찰 조건을 설명한다. 수익이나 방향을 보장하지 않는다.

알고리즘·점수·가중치를 사용한다면 산식·기간·정규화·선택 근거·가정·검증 범위를 남긴다. 검증되지 않은 가중치·허위 정밀도·근거 없는 인과를 만들지 않는다. 결측은 공식 endpoint·조회일·페이지·필드 매핑을 먼저 진단한다. 미구현 경로를 API 부재로 단정하지 않는다. 지원 API와 검증된 계산 모두 없는 항목만 공개 화면·필수 입력·프롬프트에서 제외하며 내부 설계는 보존한다.

외화 금액 첫 등장에 확인된 최신 환율로 계산한 원화 환산액과 환율 기준일을 괄호로 한 번 표기한다. 원통화·금액 배율·환율 통화방향·고시일·조회시각·출처를 보존하고 변환을 결정론적으로 검사한다. 휴일에는 최근 실제 고시일을 명시한다. 환율을 조회하지 못했으면 오늘 환율이나 환산액을 만들어 넣지 않는다.

빈 섹션 제목, 원문 덤프, 상투적 고정 문구만으로 검수를 통과시키지 않는다. 각 실제 산출물에서 근거와 산문 연결을 확인한다.

## 조회 수신과 보고서 근거의 구분

HTTP 또는 MCP 조회 성공만으로 보고서 근거 사용을 허용하지 않습니다. 같은 서버가 발급하고 보고서 조립 도구가 검증한 출처 영수증만 재사용합니다. `actual`·`local_view`를 직접 붙이거나 다른 자료의 영수증을 빌려 연결하지 않습니다.

현재 `get_global_index_history`, `get_global_index_period_history`, `get_overseas_ice_actions` 응답은 조회·진단 기록으로만 보존합니다. 검증된 출처 결속이 없으므로 보고서의 수치·계산·차트·해석·Goose 오피니언에는 사용하지 않습니다. 상태는 “조회 성공·보고서 사용 보류”로 구분하며, API 부재나 공급자 권한 거부로 바꾸어 설명하지 않습니다. 필요한 근거를 확보하지 못한 섹션은 생성 대상에서 제외하고 제외 이유를 검수 기록에 남깁니다.
