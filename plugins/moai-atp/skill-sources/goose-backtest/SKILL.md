# 재현 가능한 전략 검증

백테스트 엔진과 검증된 전체 이력은 미구현입니다. 결과를 지어내지 않습니다.

1. 전략 버전/해시, 파라미터와 시도 횟수, 시점별 universe, 데이터 vintage·정정·기업행사·상장폐지, 시장·거래일·통화·가격 조정 기준을 입력 계약으로 고정합니다.
2. 신호가 관측되는 시각과 체결 가능한 다음 시각을 분리합니다. 수수료·당시 세금·매수/매도 차이·슬리피지·스프레드·수량 단위·부분/미체결·유동성/거래량 한도·현금·마진·환율을 각각 명시합니다. 근거 없는 세율과 체결률을 기본값으로 넣지 않습니다.
3. 데이터 담당은 point-in-time과 미래정보·생존편향을, 실험 담당은 학습/검증/최종 holdout 분리·워크포워드·중복 표본·파라미터 탐색·선택편향을, 검수 담당은 누수와 계산 재현을 점검합니다. 순차 실행이 기본이며 실제 허용된 독립 agent가 있을 때만 병렬 검토를 주장합니다.
4. 결과에는 gross/net 수익, 맞는 통화·총수익 벤치마크, 최대 낙폭과 회복기간, 변동성, 회전율, 거래/독립 표본 수, 비용 민감도, 구간별 표본 밖 성과, 시도 장부와 재현 manifest가 필요합니다. 통계가 정의되지 않으면 null과 이유를 씁니다.
5. 권리 확인된 입력과 실제 실행기가 없으면 R14를 `not_run`으로 반환합니다. 단일 성공 구간을 일반 성과로 발표하지 않습니다. 실계좌와 주문을 연결하지 않습니다.

출력은 R14 실험 명세 또는 실제 실행이 있을 때만 그 실행 영수증·검수 결과입니다. `../goose/references/workflow-contract.md`에 따라 실제 MoAI Cowork HTML 템플릿/Pele adapter를 확인하고, 금융 차트는 별도 검증합니다.

수용: 미래 공시 주입→거부, 상장폐지 제외→편향 경고/완료 차단, 비용 없음→net 성과 미산출, 거래량 초과→체결 차단, holdout 튜닝→검증 무효, 데이터/엔진 없음→가짜 수익률 0. 이 지침 작성은 엔진 구현·백테스트 실행 완료가 아닙니다.
